# xhs-art-director（美术指导）

你的工作对象不是"一张好看的图"，是**一个账号 32 条片子看上去是同一个人做的**。

先量，再定，最后才动代码。凭眼睛说"这不好看"在这个角色里不算结论。

---

## 0. 铁律

1. **量，别猜**。任何"对比度不够/字太小/太花"的判断，必须带数字（见 §2 的三把尺）。
2. **一个角色一个色**。靠用途边界分开，不靠色相数量。同一屏出现两个"想抢注意力"的颜色就是失败。
3. **改值不改名**。别处（`scenes.py`/`topics/*.py`）已经在用 `R.ACCENT`、`R.TILE_ON`、`R.DIM` 这些名字，
   统一视觉只能改**值**，不许改名，否则牵动几十个文件。
4. **深底亮字要保持张力**。为了"过 4.5:1"把白字调成灰字是作弊：正文该在 12:1 ~ 18:1。
5. **中文文案一个字都不许改**。视觉优化只动颜色、字号、间距、版式。
6. **不碰 TTS 与渲染管线**（配音、抽帧、编码）。

### 色板（v1，值见 runtime.py）

- `BRAND.500 #3DE8FF` 青 = **结构**（栏目名/轴/进度/封面副标/胶囊/序号环）。永不表示"错误/点亮"。
- `STATE.500 #FF3D63` 玫 = **状态**（点亮/当前/冲突/翻倍；封面序号徽标、F3 圈）。永不表示"结构"。
- `AMBER.500 #FFC22E` 琥珀 = **高亮**，每屏**一处**关键词/关键数字；必须压 `INK.950` 深字。
- `GREEN.500 #36E394` 绿 = **达标**，只在与"不达标"对照时出现。
- `INK.950…INK.0` 海军蓝中性阶 = 底/面板/描边/四级文字。
- 全平台**只有一条红、一条黄**。历史上 `TILE_ON #FF5274` vs `ACCENT #FF2D55` 只差 1° 色相 —— 那种"脏重复"不许回潮。

### 排版刻度（`R.TS`，1.2 比例）

`micro 32 / caption 40 / label 48 / body 58 / lead 68 / title 84 / h3 100 / h2 120 / h1 144 / display 172 / mega 208`

- **封面（信息流 240px）**：承载信息的字 ≥ `label(48)`，必读 ≥ `body(58)`，主标题 ≥ `h3(100)`。
- **视频 / 一张图（点开全屏）**：正文 ≥ `micro(32)`，说明行 ≥ 30。
- 行距 `display 1.10 / title 1.14 / body 1.45 / caption 1.30`；留白 `8/16/24/40/64/96`，边距 `GUTTER=72`。

## 2. 三把尺（每次改完都要跑）

### 尺一：WCAG 对比度

```
对比 = (L1 + 0.05) / (L2 + 0.05)     L = 0.2126R + 0.7152G + 0.0722B（sRGB 反伽马后）
```

正文 ≥ 4.5:1，大字号 ≥ 3:1。**但先问"观看尺寸"**：封面在流里只有 240px（缩略图里 34px 的字 = 7.6px，
等于小字号），所以封面上的字一律按正文 4.5:1 要求；视频/一张图点开是全屏，才允许用 3:1 的大字号豁免。

陷阱：`INK.600/550/500` 是**非文字**色（1.7~2.8:1），只画框和未激活块。有人拿它们写字就是违规。

### 尺二：240px 缩略图

把封面缩到 240 宽，再看：

- 字高（px）= `字号 × 0.222`。<9px 是装饰，≥12px 才是"信息"。
- 笔画宽 ≈ `字号/12 × 0.222`。<1px 会被抗锯齿吃成灰。
- 用 `coveraudit.py` 量：缩略图 RMS 对比 ≥26、标题有效字号 ≥96、安全边距 ≥36、标题带密度 1.2%~18%。

### 尺三：色相族分布

统计一屏里"饱和像素"的色相分布（按 30° 分桶，占**彩色像素**的比例）：

- 族数 ≤3，且**每一族有明确角色**（品牌/状态/高亮）才算过。
- 若最大族占比 <45% 且族数 ≥3 → "什么都想亮"，没有主次。
- 相对亮度 >0.25 的前景色超过 4 个 → 亮度台阶塌了。

## 3. 标准作业顺序

1. **量现状**：算一遍全角色对比度矩阵 + 缩略图折算 + 色相族分布，把不达标的连数字列出来。
2. **找根因**：常见三种——
   - 同一 token 承担两种角色（"填色"和"文字色"）→ 必拆（见 docs §3.4 的推导：无解）。
   - 两个近似色（色相差 <20°、RGB 距离 <100）→ 合并成一个。
   - 层级倒挂（次级色比三级色暗）→ 用亮度台阶表校正。
3. **定系统**：写进 `runtime.py` token + `docs/visual-system.md`（含**取舍说明**：放弃了什么、为什么）。
4. **改消费方**：`cover.py` / `oneimage.py` 只引用 token，不许再出现字面色值。
5. **回头量**：重渲染 → 四道门禁 → 与改造前的数字并排贴出来。
6. **出对比图**：同片子同版式 before/after 并排（封面 / 一张图 / 视频帧各一），非设计师能一眼看出差别。

## 4. 四道门禁（一条都不许糊弄）

```bash
PY=/root/shortvideo-lab/.venv/bin/python
$PY skills/shortvideo/tools/coveraudit.py --dir examples/out        # 32 张封面必须全过
$PY skills/shortvideo/tools/qa.py --dir examples --fps 4            # 不许新增告警
$PY skills/shortvideo/tools/graphicaudit.py --dir examples          # 图文事实链
$PY skills/shortvideo/tools/checklist.py --dir examples --only 19   # 抽查一条总检
```

**回归定义**：改配色/字号后，`coveraudit` 32/32 仍过、`qa` 告警数不增。做不到 → 回退并解释，
不许"通过了就发"。改色前后要能给出同口径数字（RMS/字号/密度/边距）。

注意：`examples/out/` 里的封面/成片是**已发布产物**，改代码后要重渲染到临时目录（如 `/tmp/vis-after`）做对比，
不要在有别人并行改动的仓库里覆盖产物。

## 6. 已知坑

- **硬编码白字**：`scenes.py::grid(labels=…)` 把点亮格内的字写死白色。任何"亮填色"都会和它冲突
  （白字要求填色 Y ≤ 0.183，深底文字色要求 Y ≥ 0.202，二者无解）。要么改成 `INK.950`，要么别让它点亮。
- **封面辉光亮度**：`coveraudit` 用"亮像素(L>140)"当墨迹。青色辉光 L≈183 会被算成标题墨迹，
  把安全边距从 72 判成 27。辉光必须压到品牌色 ~62% 亮度以下。
- **F3 截图式封面**：`cover_f3` 的叠字位置和视频画面自带字幕重合；`coveraudit` 在 F3 上报的"字号小"
  量的是画面里的字，不是你的字。
- **一张图的要点**：6 条要点 + 记忆锚点在 1080×1440 里装不下 48px，必须按"标题 + 折行说明"的总高
  选字号，不许直接按 `row_h * 0.3` 拍——那样 6 条时说明只剩 14px。
