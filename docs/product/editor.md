# 剪辑台（ui/app）—— 产品设计说明

> 这一版的目标不是"再加几个命令行参数"，而是把它做成一个**能坐着干活的工作台**。
> 对标的是剪映专业版、即梦这类桌面编辑器的心智模型：素材 → 时间线 → 预览 → 检查 → 导出。

## 1. 对标拆解：它们的"专业感"到底从哪来

我把剪映/即梦让人觉得"这是个产品"的东西拆成五条，逐条落到实现上：

| # | 它们做的事 | 我们怎么落 |
|---|---|---|
| 1 | **三栏 + 时间线**，眼睛不用离开画面 | CSS Grid：顶栏 48 / 左轨 64 / 画布 1fr / 检查器 336 / 时间线 196 |
| 2 | **播放头一动画面就变**，没有任何"确认"按钮 | `GET /api/frame?t=`，服务端渲单帧，实测 30–90ms；拖动时限流 12fps |
| 3 | **改什么就地改**，右侧检查器跟着选中项走 | 选中镜头即检查器上下文，改完 400ms 防抖自动保存 |
| 4 | **永不丢稿** | 服务端 `out/<slug>/history/` 留 40 份快照 + 客户端撤销栈 + 防抖保存 |
| 5 | **导出是全流程里最重的一步**，所以要给进度 | 导出弹层解析 `渲染 120/1104` 做真实进度条，完成后回填用时 |

## 2. 信息架构

```
顶栏   片库 · 项目名 · 保存状态 · 撤销/重做 · 质检 · 导出
左轨   素材 / 配音 / 主题 / 检查 / 快捷键（抽屉式，不占画布）
画布   9:16 预览 + 传输控件（首帧/上帧/播放/下帧/末帧 + 时间码 + 当前镜头）
检查器 镜头（类型/时长/起始/口播 + 语速体检）· 项目（主题/配音/规格）· 成片检查
时间线 标尺 + 视频轨（可拖边缘改时长）+ 字幕轨 + 音频轨 + 播放头
```

## 3. 三条轨道为什么都要有

只画视频轨，用户就不知道"这条片子里到底有没有字幕、配音有多长"。
- **视频轨**：镜头块，缩略图取镜头起始后 0.4s 的帧；
- **字幕轨**：按标点切句、按字数分配宽度（导出时用真实配音时长重算）；
- **音频轨**：波形是占位图形 —— **真实波形要跑完 TTS 才有**，这里不假装，

  但长度严格等于镜头时长，所以"哪里会哑"能一眼看出来。

## 4. 预览的诚实约束

预览时间线用配置里的 `min_dur` 拼，**不跑 TTS**，所以：
- 构图、文字、节奏比例是对的；
- 每镜真实时长以导出为准（配音脚本可能把镜头撑长 0.2–0.4s）。

这条必须写进界面说明，否则"预览 36.8s / 导出 38.2s"会显得像 bug。

## 5. 交互约定（对齐剪辑软件肌肉记忆）

| 操作 | 行为 |
|---|---|
| 空格 | 播放 / 暂停 |
| ← / → | 逐帧；按住 Shift 跳 1 秒 |
| Home / End | 首帧 / 末帧 |
| 点片段 | 选中 + 播放头跳过去 |
| 拖片段右缘 | 改时长（2–30s），实时重排后续镜头 |
| 点标尺/空白 | 拖播放头 |
| 点字幕/音频块 | 跳到该位置 |
| ⌘Z / ⇧⌘Z | 撤销 / 重做（含时长与主题） |
| ⌘S | 立即保存 |
| ⌘E | 导出 |
| 滚轮 / Ctrl+滚轮 | 横向滚动 / 缩放时间线 |

## 6. 已知短板（下一步）

1. 片库首页还是旧版，视觉与剪辑台不统一；
2. 没有"新建项目"入口和模板（即梦的模板流是它的核心竞争力）；
3. 导出完成后没有成片预览与发布素材（标题/话题/封面）的一屏交付；
4. 长片（>12 镜）的时间线缩略图才做懒加载，目前是全量；
5. 撤销栈只在内存，刷新页面即失效。
