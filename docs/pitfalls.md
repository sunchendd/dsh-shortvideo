# 踩坑记录（按"坑的形式"分类，不是按时间）

> 23 轮迭代里真正花掉时间的，几乎都不是"功能没写"，而是**写好了但没生效 / 生效了但方向反了 / 数字对了但口径错了**。
> 这份记录的价值在于：下次遇到同类现象，先按这里的分类去怀疑，而不是从头调参。

---

## 一、"改了但没生效"（静默失效最贵）

| 现象 | 真因 | 现在怎么防 |
|---|---|---|
| 调 `voice.rate` 语速毫无变化 | preset 的情绪表（rule +7%）**整个覆盖** base rate | 改成全局偏移叠加；受控实验（4.38s vs 4.38s）已在 SKILL 记录 |
| 调 `mood_tuning` 只差 0.1s | 当时是缓存命中，wav 没重新合成 | 验收看"配音用时"是否为 0.0s（=命中缓存） |
| 改了 `min_dur` 重渲，节奏没变 | `tighten.py` 读的是 build 里的 wav，**新文案要重渲才有新 wav** | 顺序固定为：改文案 → 渲 → tighten → 再渲 |
| 调紧了峰值上限，音频还是"热"的 | 峰值常量没进 TTS 缓存键 → 复用旧音频 | 峰值常量纳入 `_cache_key` |
| `cards`/`list` 的 `note` 不显示 | 渲染函数没接这个字段 | 由队友报告后补 `_note()` |
| 高亮的词"消失" | `emphasis` 必须是**分句内连续子串**，否则静默不匹配 | 写进角色 skill；选题时先核对原文 |
| `ease_out` 做的"呼吸"看不出来 | 缓动在前段就到顶，后段等于没动 | 改线性；用像素差验收（518px vs 518px 说明没动） |

**通用教训**：做"生效性验证"要用**受控实验 + 数字**（同一输入，只改一个变量，比时长/像素量），
不能靠"看起来好像快了点"。

### 1.5 "只在出错时才炸"（异常路径比正常路径更需要跑一次）

这类 bug 最阴：正常跑一万次都不出现，一出问题就把"降级"变成"崩溃"。

| 现象 | 真因 | 修法 |
|---|---|---|
| 配音被网络抖动降级后，整个渲染崩 | `shots[i]` 未定义，但前两个条件**短路**，只有静音段才会求值到它 | 改用 `timeline[i]`；用 `engine: silent` 强制降级做回归 |
| 旁白超 38 字直接崩 | 那条 warn 的 f-string 用了未定义变量 `n` | 改 `n_char`；用"故意超长"的 content 回归 |
| `degraded` 算完没人用 | 没传给 `lint_script`，"这几镜语速已跳过"的提示从未出现 | 接线 + 回归看输出 |

| 配音缓存目录少算一级（落到 `skills/.audiocache`） | `os.path.dirname` 连了几次没数清 | 每次都在新建空缓存 → 全部重合成 → 网络一抖就出半截音频。打印一次真实路径即可 |
| edge-tts 返回**截断音频**（0.22s，还带词时间戳） | 连接中途重置但没抛异常 | 加"最短合理时长"检测（字数/7 秒 × 0.6），低于下限当失败重试；否则坏音频会进缓存永久污染 |

**纪律**：凡是有 `try/except`、`降级`、`fallback`、`静默跳过` 的分支，
都要能用一个开关（`engine: silent`、超长输入、缺失文件）把它强制走一遍。

**配音降级的完整恢复流程**（实测）：

```bash
# 1. 症状：[lint] [!] 配音降级为静音占位：hook, rule, ...
# 2. 识别：这些 wav 旁边没有 .words.json（边缘词级时间戳就没写）
# 3. 恢复：必须 --clean 重跑（否则 tighten 会按静音时长写坏 min_dur）
make.py ... --clean
tighten.py ... && make.py ...
```

## 二、"生效了，但方向反了"（调参调到反面）

| 动作 | 期望 | 实际 |
|---|---|---|
| 给动效密集的 kind 加 2.4s 余量，让动画演完 | 画面更从容 | 所有镜头都顶到 cap，**全片节奏变平**（动画是按比例走的，缩短镜头不会"演不完"） |
| 用均值量 pulse 风格 BGM 的音量 | 比较 BGM 大小 | pulse 是密集打击乐，间隔里均值极低 → 误判"小了 12dB" |
| 用绝对门限量人声电平 | 比较响度 | 把停顿比例混进来，同一批音频算出 ±2.7dB 假差异 |

**通用教训**：指标口径必须在**同一把尺子**下横比（和 tts 归一化同口径的"门限 RMS"、
以"90 分位"代替均值），否则结论会整个反过来。

## 三、开场与节奏（直接决定完播）

1. **元素到场按比例是最容易忽视的坑**：4.9s 的镜头按 0.5 比例，第二个元素 2.5s 才出现，
   前 1 秒几乎空白。现在 <6s 的镜头一律按**绝对时间**（1.7s 内全部到场）。
2. **`stat` 的计数从 0 起跳** = 前 0.5 秒屏幕上是"0"。改成从 60% 起跳，开场墨量 0.59% → 3.18%。
3. **一个字符/两张空卡片撑不住开场**：`compare`（空框）和单字符 `stat` 作为钩子太薄，
   钩子优先 `big`（大字 + 高亮）。
4. **成片"数完就僵"**：静态帧会让观众怀疑卡了。给 `stat`（呼吸）、`bars`/`cards`/`flow`（扫光）
   加了几乎察觉不到的微动，`timeline` 本身就在连续生长。
5. **"连排长镜头"**：单镜都不超 9s，但两个 8.6s 连在一起就是一段闷段落。
   解法不是调时长，是**删字**（01/12/13 各删 3~5 字后 pace 从 B 回到 A）。

## 四、文案与音画一致

1. **画面上的数字旁白必须念出来**，否则 lint 报"数字口播里没说"（水印 `ghost` 例外，已进白名单）。
2. **数字最占音节**：「26 个码字里，17 个是校验」念出来就是 5.7 音节/秒。
   短版一镜约 12 字，超出就删字。
3. **引导词检查**：结尾没有"关注/收藏/评论区"会扣分（CES 里关注权重是点赞的 8 倍）。
4. **封面 highlight 必须是完整语义单元**：`"算出来"` 这种半截词会把词切断（08/12 都踩过）。
5. **封面标题 ≤6 视觉字宽/行**（全宽字 1、半宽 0.5），超了直接扣分。

## 五、规则一致性（并行修改最容易埋的雷）

1. **同一约束写在两处就要同值**：短版总时长上限 `lint` 写 20s、`score` 写 22s，
   结果"score 说合格、lint 说超标"。现在两处都 22s，并互相注释提醒。
2. **短版/长版两套余量不能混跑**：`tighten.py` 曾没有 `--only`，一次把 78 个长版镜头
   按短版参数压到 ≤6.5s。现在 `tighten`/`pace` 都支持 `--only`。
3. **阈值要双向校准**：每条新检查（开场空白、开场偏薄、字幕缺失、画面太空）都要
   ① 在好片子上不误报 ② 在"人为造坏"的片子上能抓到。字幕缺失的假告警（0.7s 逗号间隙）
   就是这么被发现的。

## 六、看图与验收

1. **不要在缩略图上判断文字**：我在 50% 拼图上把「翻一倍」读成「翻三倍」，差点去修一个不存在的 bug。
   文字一律全尺寸裁切确认。
2. **量化验收优先于主观感觉**：扫光"淡不淡"用像素差说话（1.4 万 px 是细线，16 万 px 是色块）。
3. **缓存与场景**：qa/loudaudit 都有"样本不足跳过"的保护（停顿段 <8 个时不比 p90），
   否则 17 秒的短版会被误判。

## 附：本轮（第 23 轮）确认的两条新纪律

- 任何"调了参数没效果"的情况，先问三件事：**是不是被上层覆盖了 / 是不是命中缓存了 / 统计口径对不对**。
- 任何"新加的检查"，先造一个坏样本证明它能抓到，再放到好样本上证明它不误报。
