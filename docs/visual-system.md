### 0.2 240px 缩略图可读性（信息流真实尺寸，缩放系数 240/1080 = 0.222）

| 角色 | 原图 px | 缩略图 px | 笔画 px | 结论 |

代码事实（`cover.py` 改造前的实测字号）：标签 **34px**、栏目名胶囊 36px、副标下限 **36px**、CTA **40px** ——
折算到 240px 就是 **7.6 / 8.0 / 8.0 / 8.9 px**，笔画 0.63~0.74px。
在 240px 宽下**逐行**量墨迹（阈值 L>140）也印证：最细一行墨迹高中位只有 **9px**（≈51px 字号），
32/32 张都存在 <120px 的字号行。结论：封面主标题扛得住信息流，**副标/标签/CTA 在流里等于装饰噪点**。

### 0.3 色相/明度分布：什么都想亮

改造前 17 个 token 里相对亮度 >0.25 的有 10 个，色相横跨 9 个族
（`0/36/50/153/187/213/219/221/348`）。视频前景同时存在 5 个高亮度色

层级倒挂（最伤的一条）：封面副标 `#FF2D55` 相对亮度 **0.238**，比标签 `#9AA3AE` 的 **0.361** 还暗，
对比度 5.19 < 7.41 —— 二级信息比四级信息更不显眼。

### 1.3 层级亮度台阶（修掉倒挂）

`白 1.000 > 青 0.659 > 琥珀 0.600 > 绿 0.579 > 次级字(INK.300) 0.389 > 三级字(INK.400) 0.284 > 状态 0.255`

- 主标题最亮，其次品牌/高亮，文字里"越次要越暗" —— 亮度台阶与语义层级**同向**。
- 琥珀（0.600）刻意略低于青（0.659）：高亮块靠**面积 + 深字反差**抢眼，不靠"更亮"，
  这样青仍然是"账号色"，琥珀只是"贴纸"。
- 状态玫最暗（0.255）但面积小、饱和度高，符合"状态是点，不是面"。

## 2. 排版刻度（落成 `runtime.TS` / `LEADING` / `SPACE`）

1.2 比例、偶数取整，1080 画布基准：

| token | px | 240px 缩略图 | 允许承载 |
|---|---|---|---|
| `micro` | 32 | 7.1 | 只装饰（序号内、极短标注） |
| `caption` | 40 | 8.9 | 胶囊文字、页脚署名、一张图说明行 |
| `label` | 48 | 10.7 | 标签（有底色衬托）、CTA、栏目名 |
| `body` | 58 | 12.9 | **封面/信息流必读文字的下限** |
| `lead` | 68 | 15.1 | 副标 |
| `title` | 84 | 18.7 | 三级标题 |
| `h3` | 100 | 22.2 | 主标题下限（3 行） |
| `h2` | 120 | 26.7 | 主标题（2 行） |
| `h1` | 144 | 32.0 | 主标题（1 行） |
| `display` | 172 | 38.2 | 短版封面主标题 |
| `mega` | 208 | 46.2 | 单行巨字（保留位） |

行距：`display 1.10 / title 1.14 / body 1.45 / caption 1.30`。
留白节奏：`XS 8 / SM 16 / MD 24 / LG 40 / XL 64 / XXL 96`，安全边距 `GUTTER = 72`（= 9×8）。

**什么时候可以低于 48**：只有"点开全屏看"的载体（视频、一张图）。判据不是"图多大"，而是**观看尺寸**：
封面在信息流里 ≈240px 宽（×0.222），一张图/视频点开 ≈1080px 宽（×1.0）。所以：

- 封面：任何承载信息的字 ≥ `label(48)`，必读 ≥ `body(58)`，主标题 ≥ `h3(100)`。
- 视频：字幕/注脚按原尺寸看，`caption(40)` 起可用（现状 30~46，见 §5.1 未迁移部分）。
- 一张图：正文 ≥ `micro(32)`，说明行 ≥ 30。

只认识 `R.INK / R.BRAND / R.STATE / R.AMBER_SCALE / R.TS`；`art.py` 的 `PALETTES` 同样由 token 推导。

### 3.4 为什么"一个 token 两种角色"必须拆（推导）

设背景 `INK.850`（Y≈0.006）：

- 一个色当**深底上的文字**要 ≥4.5:1 ⇒ `(Y+0.05)/0.056 ≥ 4.5` ⇒ **Y ≥ 0.202**
- 同一个色当**白字的底**要 ≥4.5:1 ⇒ `1.05/(Y+0.05) ≥ 4.5` ⇒ **Y ≤ 0.183**

无解。所以旧 `TILE_ON` 无论取什么值都不可能两边都过 —— 这不是"挑颜色不小心"，
是**角色没拆**。新系统里「填色」和「文字色」是两族（`BRAND/STATE` 有 600/700 深填档，
文字统一用 500 档），`scenes.py::grid` 里那句硬编码白字因此仍是潜在缺陷（§5.2）。

## 4. 取舍说明（放弃了什么，为什么）

1. **放弃"红 = 品牌"**。封面原来用 `#FF2D55` 当主色，是 `docs/xhs-playbook.md §3` 的旧约定。
   但视频里红/玫早就是**状态**语义（点亮、当前、翻倍），再拿它当品牌，品牌色和状态色会互相污染。
   视频是主载体（151 帧/32 条 vs 每片 5 张封面），所以统一到**青**，红降级为状态。
   **代价**：封面在暖色信息流里少了一点"颜色抢眼"；补偿是把琥珀词块做成每张图唯一的高饱和暖色——
   它面积小但对比 12.5:1，在 240px 下反而是最先把眼睛钉住的东西。
2. **放弃 `#FFD400` 纯黄**，统一到 `#FFC22E`。纯黄在 OLED 上会色溢（尤其缩略图缩放后边缘发绿），
   而且和琥珀 `#FFB547` 差 14° 属于"脏重复"。新琥珀深字对比 12.5:1，仍然刺眼但可控。
3. **放弃"每条片子一套 accent"的灵活性**。`cover._cfg` 仍支持 `cover.accent` 覆盖，
   但**默认值全部来自 token**，且 `examples/` 32 条没有任何一条覆盖过 —— 说明这个自由度没人用，
   留着只会让账号花色变杂。
4. **放弃封面纯色底**，换成与视频同一条渐变 + 点阵。代价是封面不再是"干净的纯黑"，
   但换来"同一条片子的封面和画面是同一张脸"。
5. **放弃底图 4 套的"冷暖紫三原色"**，`cool` 的紫（252°）和 `warm` 的橙都没了，
   四套压成"品牌青族的深浅变体"。代价：一张图的 A/B 变体之间差异变小（只有明度/纹理差）；
   收益：任何底图都不会和高亮词块打架。
6. **放弃"用亮度表达主次"的做法**，改成"用面积 + 亮度台阶 + 语义边界"：
   最亮的是主标题，其次才是品牌/高亮；状态色故意压到最暗（0.255），因为它只该是"一个点"。
7. **放弃把视频 deck 的字号一次性迁到 `TS`**：`topics/deck.py`、`scenes.py` 不在本次授权改动范围，
   硬改会和别人冲突。所以视频字号仍是历史值（28~92），本次只统一了**颜色**与**文字亮度**；
   迁移路径写在 §5.1，谁动 deck 谁按表迁。
8. **放弃"为了达标把对比度调到发灰"**：所有深底亮字仍保持 11:1~18:1，
   没有一处因为"要过 4.5"而被削到 5:1 附近（唯一接近下限的是 `INK.400` 5.99:1，它本来就是辅助信息）。

### 5.4 副标色由青改灰（Lead 复核后追加）

美术指导把封面副标设成品牌青 `#3DE8FF`。实测亮度 **Y=0.659**，是主标题白 `Y=0.886` 的 **0.74 倍**
——台阶太浅，副标和主标题抢层级，**正是 §0.3 诊断过的"无亮度台阶"在副标上重演**。
改副标为中性浅灰 `SUB_INK = #CED8E8`（Y≈0.69，但饱和度 0 → 视觉后退），
封面四层由此分明：

| 层 | 色 | 用途 |
|---|---|---|
| 1 | 白 `#ECF2FF` | 主标题（唯一最大字） |
| 2 | 琥珀 `#FFC22E` 块 + 深字 | 数字高亮（唯一高饱和暖色） |
| 3 | 浅灰 `#CED8E8` | 解释/副标 |
| 4 | 青 `#3DE8FF` | **结构语义**：栏目、时长胶囊、标签、边框 |

青色不参与"信息强弱"，只标记"这是系统元素"——这条边界比原来的"青=主体强调"更好守。


## 7. 多主题（v2）：8 套配色，按题材分派

一套"深海军蓝 + 青/玫/琥珀"用 32 条片子，在信息流里就是"黑底红字"的一坨。
现在有 8 套**完整语义色**（不是只换 accent）：每套自带中性阶 INK、BRAND/STATE/AMBER/GREEN、底图光斑。
定义在 `shortvideo/themes.py`，切换用 `content.json` 的 `"theme"` 字段。

| 主题 | 明暗 | 一句话 | 适合 |
|---|---|---|---|
| `midnight` 深海夜 | 深 | 默认，冷静密度高 | 通用科普 |
| `jade` 苔玉 | 深 | 深绿 + 玉青 | 生物/自然/健康 |
| `aubergine` 紫檀 | 深 | 深紫 + 藕荷 | 科技/抽象/心理 |
| `noir-gold` 黑金 | 深 | 近黑 + 金 | 财经/历史/权威 |
| `graphite` 石墨 | 深 | 纯中性，几乎无彩 | 极简/工程/数据 |
| `porcelain` 青花瓷 | 浅 | 白底 + 靛蓝 | 万物皆可，最像出版物 |
| `rice-paper` 宣纸 | 浅 | 暖白纸 + 朱砂 | 人文/生活/厨房 |
| `arctic` 极地 | 浅 | 冷白 + 深青 | 医学科普/高密度 |

### 7.1 三条实现上的硬规矩

1. **浅色主题的 INK 阶是反的**：`950` = 最浅（底）、`0` = 最深（主标题）。
   这样既有代码（`BG=INK.950`、`FG=INK.0`、`TEXT=INK.50`）不用改一行就成立。
2. **压块字必须按极性算**（`R.ON_BLOCK`）：深色主题的块是亮的 → 压深字；浅色主题的块是深的 → 压白字。
   写死任何一种，另一半主题上不可读（浅色主题靛蓝块压近黑字只有 1.6:1）。
3. **视频不跟着浅色主题变**：deck 的 ghost/glow 是按深底调的，硬套会脏。
   浅色主题的片子，视频回退到同气质深色（`porcelain→midnight`、`rice-paper→noir-gold`、`arctic→midnight`），
   封面与一张图仍用浅色——视频流统一，封面负责在信息流里亮眼。

### 7.2 门禁被迫跟着改（这是重点）

`coveraudit` 原来的墨迹判定写死 `luma > 140`（假设深底亮字），浅色封面一上来整张图都是"墨迹"，
边距量出 **0px**、标题带密度 **57%**，8 套主题里 3 套被误判不合格。改了两次：

- 第一次：按边带估底亮度，往两个方向找墨迹 → 仍然失败，因为浅底**底图自带的光晕和点阵**比底暗 60 以上
- 第二次：**局部背景差分**（高斯模糊估局部底，只看高频差）+ **分位数阈值**（取差异最强的前 6% 像素）

结果：8/8 主题通过、32 张老封面**零回归**、人为造的坏封面（对比 1.8 / 1.2）仍被抓住。

### 7.3 分派规则

按学科分主题，同科内交替（避免"一个学科一个色"的单调）；**长短版同题材必须同色**
（系列识别比单条新鲜感重要）。当前分布：
midnight 6 · graphite 8 · arctic 5 · jade 4 · aubergine 3 · porcelain 3 · rice-paper 2 · noir-gold 1。

## 8. 封面 v2：按"反模板化"方法推倒重来

### 8.1 为什么 v1 被判"很挫"

用户原话是「你这些真的很挫」。拿 `docs/design/design-taste.md` 的 slop 清单逐条对照，
v1 命中 6 条：

| slop 特征 | v1 的实际做法 |
|---|---|
| 什么都居中 | 标题、副标、标签、胶囊全部水平居中，没有张力也没有层级 |
| 每条片子同一个版式 | 33 张封面是同一个模板换字，信息流里一眼看出批量生产 |
| 效果堆叠 | 柔光 + 点阵 + 颗粒 + 描边 + 高亮块，五种效果同时上 |
| 强调色过多 | 青（结构）+ 琥珀（高亮）+ 玫（状态）三色抢戏 |
| 假结构标签 | 「37 秒速通」胶囊不说任何事，纯 filler |
|  timid 字号对比 | 标题 144 / 正文 48，只有 3 倍差，读起来像模板 |

结论：v1 是"能过门禁的模板"，不是设计。门禁只验对比度/字号/边距，验不出"像个模板"。

### 8.2 三个流派（`tools/cover2.py`）

| 流派 | 骨架 | 特征 |
|---|---|---|
| `editorial` 编辑部 | 左对齐 8 栏，标题占 6 栏 | 超大标题 + 行距 1.06，细线分隔，高亮只加下划线不加色块 |
| `blueprint` 蓝图 | 可见 8×10 模块网格 + 外框 | 四角等宽小标（栏目/序号/时长），数字装进 KEY FIGURE 数据板 |
| `cinematic` 电影 | 满幅渐变 + 一次径向光 | 标题行距 1.02，唯一强调色，装饰只留一条渐隐基线 |

**严禁**：居中、三色抢戏、效果叠加、filler 胶囊。

### 8.3 分配规则：相邻不许同流派

`content.json` 里新增 `cover_direction` 字段，按 slug 排序轮换分配（11/11/11），
保证**信息流里相邻两条不是同一个版式**（Variance Mandate）。这一条是硬约束，有断言守着。

### 8.4 三个自己撞出来的 bug

1. **主题没生效**：`render()` 忘了 `set_theme`，深色和浅色渲出来**量出完全相同的数字**
   （41.9/185/98）。同数字本身就是证据，只是当时差点当成"主题不影响指标"。
2. **浅色主题被映射成深色**：用了 `theme_for_video()`，而它会把 arctic/porcelain 映射成
   midnight——那是给视频用的规则，套在封面上等于浅色主题永远渲不出来。封面要用**原主题**。
3. **强调色不可见**：graphite 的品牌色是灰白 `#bcbcc6`，饱和度 0.05，跟正文对比 1.84，
   高亮画上去跟正文一个样（10 号「三成」完全看不出来）。
   修法不是拍一个阈值，而是**先量分布**：8 套主题的品牌色对背景对比最低 5.06、饱和度最低 0.05，
   于是取 4.0 / 0.25 这条线——只筛掉 graphite，不误伤任何正常主题，且**按序取第一个合格的**
   （取对比最高会把 midnight 从品牌青跳到更浅的 400，设计语言就变了）。
   graphite 回退到琥珀。

### 8.5 尺寸灾难

- `_tracked()` 右对齐忘了减总宽 → 整串字向右画出画布（编辑部 `NO.19` 被切一半）。
- 半透明大序号用 `ra`（右上）锚点 → 96px 字号向下垂到距底 24px，判"贴边"。
  改 `rd`（右下）锚点后回到 87px。
- 编辑部底部副标与标签原来画在同一行，240px 缩略图下叠字；改成副标/标签/CTA **各占一行**。

### 8.6 实测

33 张全量重渲，`coveraudit` 33/33 通过；中位对比 39.5、字高 165px、边距 96px、墨量 6.0%。
浅色主题 6 张对照样本也全过（对比 34.0~55.5）。

## 9. 一张图 v2 与预览台 v2（同一条纪律）

封面治完之后，「一张图」和「预览台」还是老样子——用户会把一张图当图文笔记发出去，
它比封面更"被读"，所以它的问题更致命。

### 9.1 一张图 v1 的四个 slop

居中排版、每个要点套一个圆角面板、序号用彩色圆点、底图是模糊渐变色块。
四个加起来就是"AI 生成的信息图"的标准像。

### 9.2 v2 的改法（`tools/summary2.py`）

| v1 | v2 |
|---|---|
| 全居中 | 左对齐单栏，正文 measure ≈20 字 |
| 彩色圆点编号 | 等宽数字 01/02/03，单一强调色 |
| 每个要点一个圆角盒子 | 行间 1px 细线，不套盒子 |
| 记忆锚点在居中面板里 | 左对齐大字 pull-quote + 一条强调线 |
| 模糊渐变底图 | 一层极轻的竖向渐变 |

字号不靠拍：标题与要点**联合求解**——从 (92px / 46px) 起往下试，
第一个装得下的方案胜出，候选一直延到 (46 / 24)。

### 9.3 一个必须记住的教训：溢出要报错

第一版一边画一边累加 y，还额外用 `i*per` 强行对齐，结果 6 条要点直接压在记忆锚点和页脚上
（截图一眼看出叠字）。第二版改成"先算总高再落笔"，并加了一条断言：
**画完超过可用高度就 raise**。
断言立刻抓出 21 号和 23 号（6 条双行要点），第一版是**静默**画错的——
静默失败比报错危险一个数量级。

断言之后还连修两处：
- `META_H` 估 98px、实际画 116px → 差 18px 就会溢出，改成逐项对齐绘制代码；
- 候选档位不够小（最小 30/26/12 仍差 61px）→ 一直延到 24/20/6。

### 9.4 预览台 v2（`ui/index.html`）

- masthead：60px 标题 + 11px/.26em 小标 + 右上角等宽元信息（反差，不是平均）
- 卡片零装饰：无边框/圆角/阴影/悬浮位移；角标移到**图外**（浅色封面上压黑块很脏）
- 筛选从左到右：文字 tab（下划线）+ 主题色块，不是胶囊
- 标题固定两行高，保证同行卡片底边对齐（基线节奏）
- 筛选状态写进 query（`?kind=short&theme=arctic`），可分享、也可截图复现

三个 bug 全是"看起来对、其实没生效"：
1. 「＋ 新建」的绑定被塞进 `open()` 里的 `poll` 回调，打开详情前根本不生效；
2. `render()` 末尾的 `syncURL()` 会在启动那次渲染时把 `?kind=…` 抹成 `/`，
   恢复代码再读就晚了 → 必须**启动前**读 URL；
3. 短版 content.json 没有 `title`（标题在 `publish_title`），片库里 9 条全显示成 slug；
   序号按 `/^(\d+)/` 从 slug 取，短版 slug 是 `short-03-…`，取出来是空。
