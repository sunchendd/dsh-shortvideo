# 已知问题（数字与措辞层面）

补 `kernel`/`refs` 时逐条复算发现的问题。**25 条片子的数字没有算错的**，
但下面几条属于"成立条件没交代"或"措辞不精确"，需要在**下一次能联网时重渲**才能改（改旁白 = 需要新音频）。

## 1. 18-plane-window：「方角应力高 21 倍」是模型估算

- 圆孔 `Kt = 3` 是精确解（Kirsch，(3−ν)/(1+ν) = 2.93，ν=0.33）✓
- 方角 21 倍来自 Inglis 式 `Kt = 1+2√(a/ρ)`，**只在 ρ≈1 mm 时成立**：
  ρ=0.5 mm→29.3、ρ=2 mm→15.1、ρ=5 mm→9.9、ρ=10 mm→7.3
- 真实舷窗圆角半径通常 ≥5 mm，「21 倍」是尖角极限，不是量产件数值
- **建议改法**：口播「高二十一倍」→「高十几倍」；封面「应力高21倍」同步改

## 2. 17-equal-loudness-bass：「低音少 34 分贝」依赖等响曲线版本

- 片中三组数内部自洽（40 Hz 与 1 kHz 的差随等响级 0.45 dB/方线性变化，60 方插值正好 34）
- 三套数据低频段差异明显：ISO 226 修订报告说 **Robinson–Dadson 与现行标准差达 10–15 dB**，
  而 **Fletcher–Munson 与现行标准吻合更好**（A 计权的 40 phon 曲线也被证实与现代测定一致）
- 片中取 F–M 体系，方向上无误；**具体表值建议以 ISO 226:2003 复核**
- 这条**不一定需要改**，但要知道它的前提

## 3. 03-float-point：口播说「截断」，实际是就近舍入

- 现旁白：「五十二位尾数装不下，只好截断」
- IEEE 754 是 round-half-to-even（就近舍入到偶数），不是截断
- **建议改法**：「只好舍入到最近」

## 4. 16-hex-gray-not-half：deck 注释写「gamma 2.2」，实际用的是 sRGB 精确式

- 21.6% 来自 `((0.502+0.055)/1.055)^2.4`；纯 γ=2.2 幂函数会给 22.0%
- 数字对，只是注释措辞不精确；deck 注释用户看不到，**优先级最低**

## 5. 06-commute-wage：口播/封面把 36.4 取整成 36

- 精确值 8000÷220 = 36.36，口播说「36 块」属于口语取整，**可接受**
